## 배경

광고센터는 모노레포로 구성되어 있었지만, 기존 테스트는 실제 동작을 검증하지 못한 채 통과하거나 구조를 조금만 바꿔도 깨지는 경우가 많았습니다. 로직이 한 파일에 몰린 대형 컴포넌트도 많아 수정 범위를 예측하기 어려웠습니다.

또한 상태 판정과 금액 계산 같은 핵심 로직이 클라이언트에 있었고, 주문 정보가 URL에 그대로 노출되는 등 보안 측면에서도 개선이 필요했습니다.

## 설계 원칙

판단과 계산은 서버(BFF)에서, 화면은 결과를 그리는 데만 집중하도록 역할을 나눴습니다.

구조를 크게 바꾸는 작업인 만큼, 개편 전에 테스트를 먼저 재구성하고 변경 전후 동작이 같은지 검증하면서 단계적으로 진행했습니다.

## 접근 방식

- 기존 테스트를 Vitest, MSW, Playwright 기반으로 재구성하고 CI 검사 단계 추가
- 로직이 한 파일에 몰려 있던 대형 컴포넌트를 분리하고 화면 단위 폴더 구조로 개편
- AI 에이전트로 구조를 개편하고, 변경 전후 화면과 API 요청을 비교해 기존 동작 유지 여부 검증
- Next.js API Routes 기반 BFF로 상태 판정 및 금액 계산 로직을 서버로 분리
- 진입 정보를 암호화해 URL 내 주문 정보 노출을 막고, BFF에서 인증을 판정해 클라이언트에 광고주 정보가 전달되지 않도록 개선
- Next.js 14 → 16 업그레이드, ESLint → oxlint, yarn → pnpm 도구 전환
- AI 에이전트가 따르는 지시 파일, 화면별 규칙, 작업 스킬을 바뀐 모델과 도구, 프로젝트 구조에 맞게 재구성

## 인사이트

구조 개편의 속도는 AI 에이전트로 크게 높일 수 있었지만, 결과를 믿을 수 있게 만든 건 먼저 갖춰 둔 테스트와 전후 비교 검증이었습니다.

에이전트에게 맡기는 범위가 넓어질수록, 사람이 정의해야 하는 것은 "무엇이 기존 동작인가"라는 기준이라는 점을 체감했습니다.
